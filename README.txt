Connect Studio — офлайн-версия 0.7

Распакуйте архив и откройте index.html в Chrome, Edge или Firefox.
Интернет, Node.js и Python не требуются. Документация по внешним ссылкам доступна онлайн.
Для переноса схемы с сайта: «Скачать проект», затем локально «Открыть проект».
Регулярно скачивайте JSON: автосохранение file:// зависит от браузера и папки.
Конструктор только генерирует YAML; сервисы подключает и запускает Redpanda Connect.
Целевой формат 4.68.x, обычный режим try/catch; не включайте error_handling.strict.
Проверяйте конфигурации вашей версией: rpk connect lint connect.yaml.

Label: у каждого блока, включая вложенные, есть поле Label. Новые блоки получают
редактируемое имя. Пустое поле исключает label из YAML. Имена ресурсов кэша отдельные.

Обогащение: добавьте блок, задайте request_map и result_map. Нажмите «Добавлять из
каталога внутрь», выберите вложенные HTTP, кэш, маппинг или логирование. Обработка идёт
на копии запроса, результат переносится в исходное сообщение. Выберите вложенный шаг
для редактирования; кнопка сверху возвращает к родителю. Для выхода из режима добавления
внутрь выберите блок на основной схеме или нажмите «Закончить добавление внутрь».
Вложенные шаги не должны удалять или переставлять сообщения. deleted() в request_map
позволяет пропустить запрос. Для HTTP GET request_map обычно root = "".
Пример result_map: root.user = this. Для текстового ответа: root.user = content().string().
Кэш get внутри обогащения обычно не требует собственной опции сохранения сообщения.

Дедупликация: задайте ключ, отдельный ресурс memory/Dragonfly и TTL.
Дубликаты удаляются. Для memory TTL зависит от очистки и не задаёт точное временное окно.
Memory локален экземпляру и сбрасывается при перезапуске. Dragonfly общий между репликами.
Ключ запоминается до доставки: после сбоя выхода повтор может быть удалён. Для строгой
доставки предпочтителен идемпотентный приёмник; бессрочный retry выхода может снизить риск
при временном сбое, но не решает перезапуски с внешним кэшем. Он автоматически не добавляется.

Ветки: по условию выбирается первое совпадение, иначе «Остальные события».
Во все ветки: копия каждому; медленный выход задерживает поток. В каждом выходе свои
обработчики. Правила «Ошибки» относятся к ошибкам процессоров, не к отказам доставки.

ClickHouse: настройте DSN через ${CLICKHOUSE_DSN}, таблицу, колонки, массив значений,
пакеты и параллельность. Таблица должна существовать. Пример подключения:
clickhouse://default@localhost:9000/default (TLS: параметр secure=true).

Тесты (версия 0.7):
Откройте вкладку «Тесты» и нажмите «Добавить тест». Измените пример под свою задачу.
Выберите общую цепочку, процессор по label или путь к обработчикам выходной ветки.
Вход: JSON-массив сообщений, например [{"id":1},{"id":2}].
Результат: JSON-массив пакетов, например [[{"id":1}]]. [] — всё удалено.
Проверки: JSON целиком, отдельные поля, текст или выражение Bloblang.
Дополнительно можно задать метаданные, mocks и тестовые переменные окружения.
Включённые тесты экспортируются в секцию tests файла connect.yaml.
Запуск: rpk connect test ./connect.yaml
Браузер проверяет структуру, но не запускает Connect и не исполняет Bloblang.
Тесты процессоров не проверяют доставку в выходные системы.
